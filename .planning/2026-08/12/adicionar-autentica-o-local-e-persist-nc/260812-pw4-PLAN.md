  <behavior>
    PasswordHasher:
    - `generateSalt()` returns a non-empty string, and two consecutive calls differ.
    - `hash(password, salt)` is deterministic: same password + same salt yields the same digest.
    - The same password with two different salts yields two different digests.
    - The digest never contains the plaintext password as a substring.
    - `verify(password, salt, hash)` is true for the correct password, false for a wrong one.

    Equipment adapter round-trip (through a real temp-dir Hive box):
    - An Equipment written and read back is equal field-by-field on all 11 fields.
    - `lastCalibration` and `nextCalibration` survive the round-trip as the same instant AND
      the same `isUtc` flag, so `isOverdue` / `isUrgent` / `daysUntilCalibration` produce the
      same answers before and after persistence.
    - A record with `certificateId == null` round-trips as null, not as an empty string.

    EquipmentRepository:
    - On a fresh box, `seedIfNeeded()` inserts exactly 8 records with ids '1'..'8'.
    - Calling `seedIfNeeded()` twice leaves 8 records (idempotent).
    - After deleting every record, `seedIfNeeded()` inserts nothing — deleted demo data must
      NOT resurrect.
    - `add()` then `all()` includes the new record; `update()` mutates in place without
      changing the count; `delete(id)` removes exactly one; `getById()` returns null for an
      unknown id.

    AuthRepository:
    - `register()` on a fresh box succeeds and stores a user whose persisted record contains
      neither the plaintext password nor an empty salt.
    - `register()` with a username that already exists fails, is case-insensitive about the
      collision, and does not create a second record.
    - `login()` with correct credentials succeeds and sets `currentUser`.
    - `login()` with a wrong password fails and leaves `currentUser` null.
    - `login()` with an unknown username fails.
    - `currentUser` reflects the session across a simulated restart (close boxes, reopen,
      read again) without re-entering credentials.
    - `logout()` clears the session; `currentUser` is null afterwards.
    - A session id pointing at a user record that no longer exists resolves to null
      (logged out), not to a crash.
  </behavior>
